# 星载中继通道冗余配对复核

切除故障通道后，确认剩余设备能否两两配对接管冗余职责。浏览器中录入 **3–48 个唯一通道**
与**无向兼容边**，点击「复核配对」后：

- **可配对**：展示一组覆盖全部通道的配对（每对均为录入边，按通道标识升序稳定排序）；
- **不可配对**：展示阻止完整配对的通道集合 S（Tutte 屏障）、删除 S 后的每个奇数连通分量，
  并附带可凭原图逐项核对的清单，满足 **奇数分量数 > |S|** 的严格不等式。

计算在 **Web Worker** 中按**一般图（非二分图）**语义执行 **Edmonds 缩花（blossom）算法**。

## 固定配对预演

在已取得完整配对后，值班工程师可指定一条**已录入的兼容边**为必须共同接管的固定组合：

1. 录入区下方填写固定组合的两个通道（均须已录入、彼此不同、且二者之间存在录入边），点击**「固定配对复核」**；
2. Worker 删去这两个端点后，**只在剩余诱导子图上继续按一般图求完整配对**（仍是同一份 Edmonds 缩花）；
3. **可行**：把固定组合与剩余配对合并，按通道标识升序稳定排序展示，固定组合单独标注，
   并明确全部通道有且仅有一次出现；
4. **不可行**：展示的 Tutte 阻塞集合 S 与奇数连通分量**只针对删去固定两端后的剩余通道**，
   核对项也只在剩余图上逐项计算。它证明的是“强制该绑定后其余通道失去安置机会”，
   **不是原图无法配对的失败证书**（原图换一组配对仍可能成功）。

固定边不存在、通道未知/相同、或本次通道与边输入校验失败时，均给出明确中文反馈并**清除旧的固定配对结论**；
普通「复核配对」的语义与结果完全独立。两类请求共用同一个单调递增请求序号：
发新请求前 terminate 旧 Worker，过期序号的回包一律丢弃，**固定约束结果不会被较早的请求覆盖**。

## 输入校验（均给出明确中文反馈）

| 情形 | 反馈 |
| --- | --- |
| 自环（A — A） | 拒绝 |
| 重复边（含反向书写 B — A） | 拒绝 |
| 含未知端点的边 | 拒绝 |
| 通道数非偶数 / 少于 3 / 多于 48 / 标识重复 | 拒绝 |
| 空边图（无任何兼容边） | 拒绝 |

任何失败提交都会清空上一次通过的配对，绝不保留旧结果。

## 本地运行（无第三方依赖，Node ≥ 20）

```bash
npm run build
npm start                 # 默认 0.0.0.0:8080
PORT=8091 npm start       # 自定义端口
curl localhost:8080/health
```

一键校验（测试 + 构建 + HTTP 冒烟，以退出码结束）：

```bash
npm run verify
```


## 失败证书为何可核对

Tutte 定理：图 G 有完美匹配，当且仅当对任意顶点集合 S 都有
`odd(G - S) ≤ |S|`（odd 为奇数连通分量数）。算法在最大匹配的匈牙利交错森林上取
**奇层顶点 S**，G−S 的每个奇分量恰好容纳一个无法增广的暴露根，故
`odd(G−S) = 暴露点数 = |S| + 缺额 > |S|`。

页面展示的核对项（`verifyCertificate`，仅凭原图与证书独立计算，不使用匹配过程数据）：

1. 各分量互不相交，且与 S 共同覆盖全部通道；
2. 每个分量可沿原图兼容边在内部连通；
3. 删除 S 后各分量之间不存在原图边；
4. 每个分量顶点数均为奇数；
5. 奇数分量数严格大于 |S|。
